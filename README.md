# Полка

**Из фотографий и исходных сведений — в редактируемый черновик карточки товара.**

Полка помогает продавцу перенести надписи с упаковки в характеристики, подготовить описание и проверить карточку перед ручным подтверждением. Сервис создан как решение задачи «Карточка товара за три минуты».

В центре работы — редактор: пользователь выбирает нужные характеристики, принимает подсказки с фото и решает, какой текст оставить. Можно начать с фотографий или заполнить товар вручную. Для запуска редактора и локального OCR ключ LLM не нужен.

**Версия 2.4.2 · Русский интерфейс · OCR на CPU · REST API**

## Возможности

| Задача | Что делает Полка |
| --- | --- |
| Заполнить характеристики | Конструктор с поиском, готовыми названиями и своими полями. Обязательно только название товара. |
| Перенести текст с фото | Распознаёт русские и английские надписи, предлагает значения и позволяет сверить их с фотографией. |
| Сохранить происхождение сведений | Различает ручной ввод и OCR; у принятых подсказок сохраняет связь с исходной строкой и фото. |
| Подготовить описание | Собирает текст из проверенных характеристик или, при подключении LLM, предлагает отдельный вариант описания. |
| Найти незавершённые действия | Показывает готовность, непроверенные значения, явные противоречия и рекомендации по фотографиям. |
| Улучшить текст | LLM предлагает редакторские замечания и вопросы о недостающих сведениях. |
| Оформить результат | Позволяет сравнить три оформления с одинаковыми товарными сведениями. |
| Сохранить карточку | После ручного подтверждения экспортирует JSON карточки или TXT с описанием. |

Предварительная модерация проверяет состояние черновика по внутренним правилам сервиса. Она не заменяет модерацию конкретного маркетплейса.

## Как проходит работа

1. **Создайте товар.** Укажите название, найдите нужные характеристики или добавьте свои.
2. **Добавьте фотографии.** До трёх изображений JPEG/PNG, не более 5 MiB каждое. Загрузка сама по себе не запускает распознавание.
3. **Запустите OCR по желанию.** Просмотрите подсказки, сравните текст с фото и перенесите подходящие значения в выбранные поля.
4. **Подготовьте описание.** Напишите его самостоятельно, нажмите «Собрать из фактов» или воспользуйтесь подключённой LLM.
5. **Проверьте карточку.** Исправьте замечания, разрешите противоречия и отметьте заполненные сведения и описание проверенными.
6. **Подтвердите и экспортируйте.** Подтверждение относится к конкретной версии карточки; существенные изменения требуют новой проверки.

Фотографии и LLM необязательны: ручной путь позволяет пройти весь сценарий до экспорта.

## Быстрый старт

### Требования

Для зафиксированного окружения используются:

| Компонент | Версия |
| --- | --- |
| Python | 3.13.13 |
| Node.js | 24.15.0 |
| npm | 11.12.1 |

Также нужен Git. GPU не требуется. При первой установке нужен интернет для загрузки пакетов и OCR-весов; затем локальное распознавание выполняется без отправки фотографий внешним сервисам.

Версии указаны в [dependencies.json](dependencies.json), [.python-version](.python-version) и [.node-version](.node-version). Python-зависимости закреплены с SHA-256 в [requirements.lock](requirements.lock), npm-зависимости — в [package-lock.json](package-lock.json).

### Windows / PowerShell

```powershell
git clone https://github.com/Nek1tt/polka.git
cd polka
Copy-Item .env.example .env
.\start.cmd --port 8005
```

`start.cmd` создаст `.venv`, установит закреплённые зависимости, загрузит OCR-веса с проверкой контрольных сумм и запустит сервер. Первый запуск занимает больше времени из-за загрузок. При повторном запуске существующий `.env` копировать заново не нужно.

После сообщения об успешном запуске откройте:

- [Редактор](http://127.0.0.1:8005/)
- [Swagger UI](http://127.0.0.1:8005/docs)
- [Версию работающего API](http://127.0.0.1:8005/api/v1/version)

Остановка — `Ctrl+C` в терминале сервера. Проверка папки, версии и свободного порта без запуска:

```powershell
.\start.cmd --check --port 8005
```

Для уже установленного окружения сервер можно запускать без повторной установки:

```powershell
.\.venv\Scripts\python.exe launch.py --port 8005
```

## Помощь с текстом (LLM)

LLM выполняет три задачи: предлагает краткое описание из переданных сведений, отмечает повторы и неясности, задаёт вопросы о товаре. Результат появляется отдельно от сохранённого описания. Для переноса нужно нажать «Заменить описание этим вариантом», затем проверить текст вручную.

Пример реального ответа API на синтетический товар «Футболка» с материалом «100% хлопок»:

![Предложение описания и отдельная кнопка применения в Полке](assets/readme/text-assistance.png)

### Подключение Groq

1. Создайте ключ в [Groq Console](https://console.groq.com/keys). Порядок настройки описан в [официальном Quickstart](https://console.groq.com/docs/quickstart).
2. В существующем `.env` заполните параметры:

```dotenv
LLM_PROVIDER=groq
LLM_MODEL=openai/gpt-oss-120b
LLM_API_KEY=your_api_key_here
LLM_GROQ_FREE_PLAN=1
LLM_DAILY_BUDGET=40
```

3. Перезапустите сервер. В редакторе сохраните сведения, разрешите их отправку провайдеру и нажмите «Проверить текст и предложить описание».

`LLM_GROQ_FREE_PLAN=1` сообщает приложению о выбранном бесплатном плане, но не проверяет тариф аккаунта. Доступность модели, квоты и условия определяет провайдер. У сервиса также есть собственный бюджет анализов; автоматического переключения на платную модель нет.

Адаптер поддерживает и OpenRouter с идентификаторами моделей, оканчивающимися на `:free`; переключение выполняется явно через `.env`. Проверенный живой сценарий 2.4.2 использовал Groq и `openai/gpt-oss-120b`.

### Как контролируется ответ

В [backend/llm.py](backend/llm.py) находятся инструкция модели и схема ответа. На вход передаются категория, заполненные поля без отмеченных конфликтов и сохранённое описание. Галочка ручной проверки поля не является условием его отправки. Фотографии и непринятый OCR в этот запрос не входят.

- Каждое предложение описания должно ссылаться на существующие сведения через `fact_ids`.
- Сервер проверяет JSON Schema, ссылки, буквальность цитат в замечаниях и отсутствие новых чисел в предложениях описания.
- Для Groq используется строгий структурированный ответ; дополнительная локальная валидация сохраняется. [Документация Structured Outputs](https://console.groq.com/docs/structured-outputs).
- Некорректный ответ отклоняется. Применение предложения — отдельная операция, привязанная к ревизии карточки.
- После применения описание остаётся непроверенным до действия пользователя.

**Эти проверки не доказывают смысловую достоверность.** Модель может ошибиться в формулировке или рекомендации даже при корректном JSON и существующих ссылках. Сервис не проверяет правдивость сведений продавца и не требует от него доказательств. Итоговый текст проверяет человек.

## Распознавание и предварительная проверка

Основной локальный OCR — **PP-OCRv5 mobile / eslav**, запускаемый через RapidOCR и ONNX Runtime на CPU. Для уточнения отдельных фрагментов используется Tesseract.js. Русские и английские веса закреплены по контрольным суммам; во время распознавания они не скачиваются.

Распознанные строки распределяются по характеристикам по явным русским и английским заголовкам. Это правила обработки текста, а не нейросетевая классификация категории товара. Нераспределённые строки можно перенести вручную. Оценки OCR и эвристики качества не являются калиброванной вероятностью правильности значения.

Отдельный режим Google Cloud Vision включается явным выбором и серверным `GOOGLE_VISION_API_KEY`. Только в этом режиме фотографии передаются Google. Для локального сценария он не требуется.

Готовность учитывает заполнение обязательного названия, ручную проверку сведений и описания, а также неразрешённые противоречия. Отсутствующие необязательные характеристики не становятся обязательными из-за рекомендации LLM.

## API и интеграция

Машинные контракты находятся в репозитории:

- [OpenAPI](contracts/openapi.yaml) — маршруты, запросы, ответы и ошибки.
- [JSON Schema карточки](contracts/card.schema.json) — поля, источники, ревизии, готовность и подтверждение.
- [Схема текстовой помощи](contracts/text-assistance.schema.json) — формат предложений LLM.
- [Примеры карточек](contracts/examples/) — синтетические состояния для интеграции.

Работающий сервер публикует Swagger по `/docs`, контракт — по `/openapi.json`. Версия API — **2.4.2**, формат Card — **2.2**.

| Метод и маршрут | Назначение |
| --- | --- |
| `POST /api/v1/cards` | Создать ручной черновик |
| `POST /api/v1/cards/{id}/photos` | Прикрепить фотографии |
| `POST /api/v1/cards/{id}/ocr-jobs` | Явно запустить распознавание |
| `GET /api/v1/jobs/{id}` | Получить состояние фоновой задачи |
| `GET /api/v1/cards/{id}/ocr-suggestions` | Получить подсказки завершённого OCR по `job_id` |
| `POST /api/v1/cards/{id}/accept-suggestion` | Принять OCR-подсказку в поле |
| `PATCH /api/v1/cards/{id}` | Изменить сведения и отметки проверки |
| `GET /api/v1/cards/{id}/recommendations` | Получить готовность и предварительные замечания |
| `POST /api/v1/cards/{id}/text-assistance` | Получить предложение LLM с явным разрешением отправки |
| `POST /api/v1/cards/{id}/apply-text-assistance` | Применить предложение к соответствующей ревизии |
| `POST /api/v1/cards/{id}/confirm` | Вручную подтвердить карточку |
| `GET /api/v1/cards/{id}/export?format=json` | Выгрузить подтверждённую карточку; `format=text` — описание |

Клиент должен сохранять cookie `card_session`. Для изменяющих запросов нужен разрешённый `Origin`, для операций над существующей карточкой — предусмотренный контрактом `expected_revision`. Устаревшая ревизия возвращает `409 REVISION_CONFLICT`. При работе через Swagger учитывайте то же требование к заголовку `Origin`.

Пример создания черновика и запроса рекомендаций из Python; `httpx` уже входит в зависимости:

```python
import httpx

base_url = "http://127.0.0.1:8005"
with httpx.Client(base_url=base_url, headers={"Origin": base_url}) as client:
    response = client.post("/api/v1/cards", json={
        "fields": {"product_name": "Футболка", "material": "100% хлопок"}
    })
    response.raise_for_status()
    card = response.json()

    response = client.get(
        f"/api/v1/cards/{card['card_id']}/recommendations",
        params={"expected_revision": card["revision"]},
    )
    response.raise_for_status()
    print(response.json()["readiness"])
```

Это контракт сервиса подготовки карточек. Прямых адаптеров публикации на маркетплейсах в версии 2.4.2 нет.

## Проверки

Для зафиксированного окружения 2.4.2 выполнены **114 Python-тестов и 8 JavaScript-тестов**. Зависимости установлены в чистое Python-окружение с проверкой хешей; `npm ci` также выполнен отдельно.

Проверены сохранение и восстановление состояния редактора, ручной путь до подтверждения, настоящий локальный OCR, перенос подсказок, защита сессий и ревизий, экспорт, а также валидация ответов и диагностика ошибок LLM. Через браузер пройден живой сценарий Groq: запрос → предложение → отдельное применение → ручная проверка → подтверждение. Один живой пример не является бенчмарком качества модели по всем категориям.

Повторный запуск тестов после установки пакетов и OCR-весов:

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
node --test tests/attributes.test.mjs tests/editor-state.test.mjs tests/editor-projection.test.mjs tests/ocr-selection.test.cjs
```

Обычные Python-тесты отключают внешние ключи и используют отдельный `test-runtime/`. Для проверки LLM есть [12 синтетических сценариев](scripts/evaluate_llm.py): запуск с `--run` отправляет их настроенному провайдеру и расходует его квоту. Смысловую корректность результатов оценивают вручную.

## Устройство проекта

Один FastAPI-сервер обслуживает интерфейс, API и обработку задач. Интерфейс написан на HTML/CSS и JavaScript без сборщика. Карточки и служебные объекты хранятся в SQLite, фотографии — на диске. LLM вызывается через HTTPX; агентного цикла и интернет-поиска нет.

```text
backend/               API, доменные проверки, OCR и LLM
frontend/              Редактор, библиотека товаров и оформления
contracts/             OpenAPI, JSON Schema и синтетические примеры
data/demo/             Синтетические этикетки для демонстрации и тестов
scripts/               Загрузка моделей, оценка и вспомогательные команды
tests/                 Серверные и JavaScript-тесты
requirements.lock      Полный закреплённый набор Python-пакетов с SHA-256
package-lock.json      Закреплённый набор npm-пакетов
source-manifest.json   Контрольные суммы снимка кода 2.4.2 до добавления README
```

## Данные и границы версии

- Библиотека товаров привязана к сессии браузера. Регистрации и постоянного пользовательского кабинета нет; по умолчанию срок доступности черновика — 24 часа. Для сохранения результата используйте экспорт.
- Данные локального запуска размещаются в `runtime/`, веса — в `model-cache/`. Эти папки, `.env` и ключи исключены из Git.
- В локальном режиме фотографии обрабатываются на компьютере, где запущен сервер. Для LLM текст передаётся выбранному провайдеру только по отдельному действию и согласию в интерфейсе.
- OCR может ошибаться на мелком тексте, бликах и размытых изображениях. Исправления и ручной ввод остаются частью рабочего сценария.
- Скорость зависит от фотографий, CPU и доступности API. Название исходной задачи не является измеренной гарантией выполнения за три минуты.

Автор проекта — [Nek1tt](https://github.com/Nek1tt). Сторонние пакеты и веса используются на условиях их лицензий; лицензия включённого шрифта приведена в [frontend/fonts/OFL.txt](frontend/fonts/OFL.txt).
